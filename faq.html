Choosing SQLite

Is SQLite a client-server database?

No. There's no separate server process to start, configure, or keep running. The engine is a library linked directly into your application, and the database is a single file it reads and writes.

Is SQLite "real" enough for production use?

Yes — it's one of the most widely deployed pieces of software in the world, running inside billions of phones, browsers, and desktop applications, with a test suite built around simulating failure on every allocation and write. See About for how that testing works.

Can I use SQLite in a commercial, closed-source product?

Yes. SQLite's source code is dedicated to the public domain, so there's no licence to comply with and no royalty owed, commercial or otherwise.

Using it day to day

How do I use SQLite from my language of choice?

Most languages either bundle a driver or have a well-known third-party one. See Get Started for the common ones, or check your language's package index.

What's the difference between INTEGER PRIMARY KEY and a regular rowid?

Every table has an implicit 64-bit rowid unless it's declared WITHOUT ROWID. A column typed exactly INTEGER PRIMARY KEY becomes an alias for that rowid, so it's faster to look up and doesn't need extra storage of its own.

Does SQLite enforce foreign keys?

It can, but foreign key enforcement is off by default for backwards compatibility. Turn it on per-connection with PRAGMA foreign_keys = ON;.

Concurrency and scale

Can multiple applications read and write the same database at once?

Multiple readers can access a database simultaneously, and in write-ahead logging mode a single writer can proceed while readers keep working. SQLite serialises writes rather than supporting concurrent multi-writer access the way a client-server database does — see Documentation for the write-ahead logging guide.

How large can a SQLite database get?

Up to 281 terabytes, limited by the maximum page count and page size the format allows. In practice, disk space runs out long before that theoretical ceiling matters.

My query is slow — where do I start?

Check EXPLAIN QUERY PLAN against your query first; a missing index on a column used in WHERE or JOIN is the most common cause. The SQL syntax reference covers CREATE INDEX.
